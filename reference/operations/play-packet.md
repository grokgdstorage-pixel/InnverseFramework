# Play packet

How to open the vault and produce play text. Inherited by every clone. A table’s posting exceptions live in `reference/campaign/`.

This file is not a Design manual. This file is not a setting gazetteer. This file is not the archive.

---

## Scope

This file answers:

- which pages to open before writing play
- what to return
- what not to invent
- how options must differ from one another

This file does not answer:

- Class, Skill, level, or Condition procedure (`frameworks/grand-design/`)
- spell construction (`frameworks/magic/spellcraft.md`)
- what already happened (archive / chronicle / `history.md`)
- house rules for one game (`reference/campaign/`)

---

## How to use this file

Use this file when a human asks for a play post, a reply, a narrator beat, or angles for the next post.

Do not use this file when they asked only for a Design ruling. Open `the-system.md` and the matching child instead.

Blank or `unknown` in the vault = unknown. Do not invent unless the prompt says to create it and use it now.

---

## Read order

Stop when the scene is covered. Do not open the whole vault.

1. `lore/campaign/premise.md` — which game this is
2. The person folder in play — `profile.md` → `mind.md` → `relationships.md` → `record.md`
3. `lore/campaign/places.md` — the room on the archive card
4. `lore/campaign/chronicle.md` — last beats only
5. `lore/campaign/archive.md` — **Body** of the current scene, usually the last two to four posts

Then only if needed:

- `history.md` / `history-system.md` — a past beat or announce must be cited
- a relationship card — a specific other person is on camera
- `magic.md` / `spellcraft.md` — they are using magic in this scene
- `the-system.md` and one child (`classes.md`, `skills.md`, `leveling.md`, or `conditions.md`) — the narrator asked for a Design pass, or the paste already contains an announce that must be logged
- A Design look uses the last chronicle beat plus `history-system.md`. Do not invent extra compile fields. Do not invent Archive, Eval, or Design bots.
- `lore/campaign/premise.md` Table law — this table wrote a short exception. `reference/campaign/` only if that note is too long for premise.

On `mind.md`: Personality and How their mind operates first. Then only the labeled section the scene needs.

---

## Output

**Asked for a post or reply.** Return the play text. Camera is the player character: room, actions, what can be seen and heard. Do not write an NPC’s private thoughts or feelings except as visible or audible signs.

**Asked for angles or options.** Return a short list. Each option must change act, place, or stakes. Do not paraphrase option 1. Not a finished post unless they also asked for one.

**OOC.** Default: none. Add a line only if they asked, or if the vault is missing a fact required to write the scene.

Do not treat this output as an in-world System announce. Do not treat a vault heading as spoken dialogue.

Room and body detail come from the current **Body** and the `places.md` card. Do not paste the last post’s furniture paragraph again. Do not invent a second room to make the prose feel new. If the prompt says to create a place and use it now, that wins; the narrator files it after.

Tone and limits for this game, including what erotic content is allowed or barred, live on `premise.md` under Table law. Do not invent a second list here.

---

## Stops

- Do not invent a place, faction, person, or deed that is not in the vault, unless the prompt says to create it and use it now. The narrator files that into the vault after the post.
- Do not print a Class, Skill, level, or Condition unless the narrator asked or it is already in the post being answered.
- Do not summarize the archive instead of reading **Body**.
- Do not use a wiki anecdote as table law.
- Off-screen moves are the narrator.
