# Classes

## Scope

Application manual for **one product: a Class**.

Read `the-system.md` first. Do not restate Watch, Judge, or Speak.

This file answers:

- when a first Class appears
- which Class owns a deed
- when a name is flavor and when it is a hierarchy step
- when a Class is renamed or specialized
- when Classes consolidate
- when a Class is lost or demoted
- how hierarchy changes the pool

This file does not answer:

- which Skill to pick (`skills.md`)
- when a level fires (`leveling.md`)
- Conditions (`conditions.md`)
- magic
- a list of legal Class names

## How to use

If you have not walked Watch → Judge → Product on `the-system.md`, stop and do that first.

Open this file when the product in play is a Class: first Class, same Class, new name, hierarchy step, consolidation, loss or demotion, or “which Class owns this deed.”

If the mark is only a Skill or only a level, do not use this file.

### Output

Grok ruling packet, not play-post text and not the archive Body.

Return:

1. Class outcome: none / first Class / same Class / flavor rename / hierarchy step / consolidation / loss or demotion
2. Which Class owns the deed, if they have more than one
3. One short reason
4. A range of fitting Class names or outcomes when more than one honest fit exists. Grok proposes names and hierarchy adjectives. Do not lock to a single name unless only one fits. Mark which options are the smaller marks.
5. Whether `skills.md` or `leveling.md` should open next

Narrator finalizes. Smallest Class mark that fits, unless they pick a larger honest option.

### Stops

- No Class directory.
- No Skill list.
- Do not assign a level number here. If a number is needed, open `leveling.md`.
- Do not hand a new name when the old name still tells the truth.
- Authority-granted Classes are parked. Narrator only if play uses them.
- Unique / personal Class names: narrator-only extremes. Do not invent a page for them.
- System announcement colors (gold, green, and the rest): parked. They cut across Classes, Skills, and Conditions. Do not invent a color key in this file.
- Example Class names are illustrations. Do not require them on `record.md`.
- Skill procedure is `skills.md`. Level procedure is `leveling.md`. Do not invent those procedures here.
- Refused = the offered Class or Skill dies. Deeds, events, and mindset stay. Lost = the Class leaves the living list on `record.md` and is stored. Do not store a refusal. Do not expire a loss.

## What a Class is

A Class is the role they are inhabiting or becoming.

It chooses the Skill pool and how rich that pool is (hierarchy).

It is not a job title they bought. It is not a player menu.

Mindset is a foundation, not flavor text. How they understand the deed is part of what the deed *is*. Costume without deed still does not make a Class.

## First Class

Someone with no Class in this path starts living a role.

Need mind, deed, and becoming. Mindset quality matters as much as the motion. A person who holds a gate and thinks “this is mine to keep” is not the same as a person who holds it and thinks “I am waiting to leave.”

Basic entry is allowed. Cleaning the inn and keeping it is how [Innkeeper] starts. Walking the gate as their post is how [Guard] starts. Throwing pots as the life is how [Potter] starts.

Silence if they have not lived it. A night of pretending is not a first Class.

First Class is usually modest hierarchy. That is the average, not a wall.

Wanting a crown while thinking and acting as a frightened soldier does not open a [King] path. Declaring yourself king is not enough by itself.

A first Class can sit higher when mind and deed already match that height: they hold the inner stance of the role, they act from it, and they take on the weight that role carries (command given and accepted, authority used, others moving because they spoke). Quality and intensity of that match can open a higher first Class. Wish and costume cannot.

## Which Class owns a deed

When they hold more than one Class, the deed feeds the Class that honestly owns that kind of act.

Use the path they were living in the scene, not the prettier name.

Holding extra Classes is not a fine. Time is the limit.

Mind shapes what the deed *means*. Playing a board game is not [Strategist] work if they only ever mean it as a game. The same board can feed [Strategist] if they mean it as war in miniature.

If mind and deed pull apart, do not auto-pick. Inform the narrator. List both readings. Examples of the split:

- They do the motions of a role but refuse that identity. The System may still *offer*. They may refuse. That refusal is allowed. Do not force the Class. Keep the deeds, events, and mindset that caused the offer. The offered Class or Skill itself expires. It is not sitting on `record.md` waiting to be clicked later. A later mark must be earned again from what they still are and still do.
- They hold the identity but the deeds are thin. Do not mint the higher Class. Wait or keep the smaller name.

Grok does not resolve that split in silence.

## Flavor vs hierarchy

Two kinds of name change. Do not mash them.

**Flavor.** Same height of pool, different word for the same role. [Fighter] and [Warrior] are this: the same kind of work, two names. Not every pair of combat names is flavor. If two names imply different tools, cultures, or heights, they are not this pair.

**Hierarchy step.** Richer pool. More possibilities and capability. [Soldier] → [Veteran Soldier], [Swordsman] → [Swordmaster], [Lord] → [King]. [Veteran] is an adjective example, not the only step word.

A flavor change is the same job, said differently. A step up is a different height of role.

A step up is identity plus deeds. It is not a level number by itself. A high-level [Swordsman] can still be a [Swordsman]. A [Swordmaster] is someone the path has already made into a higher thing.

Use an **adjective** ([Veteran Guard]) when the path is the same work, grown. Use a **new noun** ([Swordmaster], [King]) when the role itself changed height or kind.

**[Veteran]** is a hierarchy adjective, not a Class locked to [Soldier]. It can sit on any path where earned experience and wisdom in *that* work would raise the role: [Veteran Guard], [Veteran Sailor], and so on. It is one example of a hierarchy word, not the only one. Grok may propose other adjectives. Narrator picks.

It marks wisdom earned in the path, not years on a calendar. That wisdom can come from long service at low intensity, or from a shorter stretch of high-intensity events that force the same learning faster. Either route can justify the step. A long quiet stretch with nothing learned is not enough. A brutal stretch that does not change how they understand the work is not enough.

Narrator may override.

## Name change and specialize

When the old name no longer tells the truth, the name can change without a full consolidation.

The novels print this as “Conditions Met: old → new.” In this kit that line is a **Class name change**. It is not the Conditions page and not `conditions.md`.

Specialize inside a path: [Guard] → [Gate Guard] if the life narrowed and that name is truer. Jump to a different path only if they have actually left the old one.

Smallest name that still tells the truth. Do not gild it.

## Consolidation

More than one Class becomes one when they live as one path, not when they merely hold two titles.

The old names fold. They are not extra Classes anymore.

Do not consolidate when a smaller name change would tell the truth. Rename or specialize first if that is enough.

The new Class’s pool is the pool of that one path. How rich it is follows hierarchy. Which Skills appear is `skills.md`. What level number the new Class shows is `leveling.md`. This file only says the Class identity changed. Do not guess the resulting level.

Refuse consolidation if they still live two separate lives and only want one prettier line on `record.md`.

## Loss and demotion

A Class can be lost or stepped down. Idle time is not enough. Someone who stops pursuing a Class still holds it, and its Skills, until the role itself breaks.

Retirement without abandonment may be a flavor rename (the same height, said as someone who has set the work down). That is not loss.

Loss or demotion needs a real break in mind and deed, for example:

- The role is taken from them and they no longer hold it (a [King] overthrown). The Class may drop in hierarchy. Skills may convert to fit the new, lower role. Conversion is `skills.md`. The new identity is this file.
- They flee the role and drop the mindset and duties that made it true. The Class may go, or a much smaller Class may replace it.

Store what was lost. The old Class name, its height, and its Skills stay on `record.md` under Stored. Do not treat loss as deletion.

Restore only as much as they have actually reclaimed in mind and deed. A partial return is allowed: a smaller Class, a lower height, or only some of the stored Skills. A full return needs a full return of the role. How Skills convert or return in detail is `skills.md`. If that file is missing, report identity plus “stored; restore only what they have reclaimed” and stop.

Do not strip a Class because a week was quiet. Do not keep a [King] Class on someone who has ceased to be one in mind and deed.

If loss vs demotion vs flavor-retirement vs partial restore is unclear, inform the narrator. List the readings. Prefer the smaller identity change that still tells the truth.

## Hierarchy and the pool

Higher hierarchy = richer Skill pool.

Level still multiplies inside whatever Class they hold.

A Level 40 [Soldier] is not a [King]. A new [Swordmaster] is not automatically higher-level; they have a richer pool at whatever height they actually hold.

## Examples

Not a catalog.

**First Class, modest.** They keep a ruined building alive. Mind: this place is theirs to keep. A place-keeping Class at modest hierarchy. Not [Ruler].

**First Class, exception.** They take command in a collapse, others obey, they accept the weight and think as the one who must hold the line. A higher first Class may be honest. Declaring a title while still thinking as prey is not this.

**Silence.** A [Guard] holds the same gate with the same inner story. Same Class. Whether they level is `leveling.md`.

**Player want.** They ask to become a [Knight] after a quiet week of gate duty. No matching becoming. Same Class or silence. Not [Knight].

**Owns the deed.** [Potter] and [Soldier] on `record.md`. They spend the scene at the wheel. The deed feeds [Potter].

**Mind shapes the deed.** They play a tactical game as a game. It does not feed [Strategist]. The same game, meant as war, can.

**Mind and deed split.** They fight and refuse every combat Class. Offer the combat reading and the refusal. Keep the deeds and mindset. The offered Class expires. Inform the narrator. Do not force the Class.

**Packet shape.** Same gate year, two honest reads: same [Guard] (smaller) or [Veteran Guard] (step). List both. If they refuse [Veteran Guard], keep the year’s deeds; do not leave [Veteran Guard] sitting on `record.md`.

**Flavor.** [Fighter] or [Warrior] for the same fighting life. Same height. Two words.

**Hierarchy step.** A [Swordsman] is no longer “someone who uses a sword.” Other swordsmen measure against them. [Swordmaster] may be a step up. Skill picks are `skills.md`.

**[Veteran].** Years on the line that taught them, or a short war that taught them as much. [Veteran Guard] or [Veteran Soldier] may be honest. The word is a hierarchy adjective on a fitting Class, not a [Soldier]-only name. Time served with nothing learned stays the base Class.

**Specialize.** They only keep one gate, and that gate is the life. A narrower gate-keeping name if that is truer. Not [Captain] unless they command.

**Consolidation earned.** [Leader], [Scavenger], and [Tinkerer] have become one life. One Chieftain-like Class. Old names fold. No level number from this file.

**Consolidation refused.** [Strategist] and [Baker] still lived as two lives. Keep both.

**Demotion.** A [King] is unseated and no longer rules in mind or deed. The [King] Class does not stay. A lower ruling or fallen-ruler Class may replace it. Store the [King] Class on `record.md` under Stored. If they reclaim only part of that role, they get only part of it back. Skill conversion is `skills.md`.

**Not loss.** They retire from the gate and still think of themselves as that craft. Flavor rename or same Class. Skills remain until a real break.

## Design notes

- Class names in examples are patterns, not required Classes.
- Name-change lines in the novels are Class identity, not the Conditions child.
- [Veteran] is a hierarchy adjective for earned wisdom on a fitting path, not a [Soldier]-only Class. Grok proposes other adjectives.
- Adjective = same work grown. New noun = the role changed height or kind.
- Refused offers: deeds and mindset stay. The offered Class or Skill expires.
- Lost or demoted Classes and Skills are stored on `record.md` and can return only as far as the role is reclaimed.
- Authority-granted Classes: narrator only if play uses them. Do not invent a page.
- Unique / personal Class names stay narrator-only. Do not invent a page.
- System colors (gold, green, blue, red, and others) belong on a future colors page, not here.
- Consolidation and demotion do not invent Skill lists or level math here.
