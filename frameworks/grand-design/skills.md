# Skills

## Scope

Application manual for **one product: a Skill**.

Read `the-system.md` first. If the Class itself might change, read `classes.md` before picking a Skill.

This file answers:

- which pool a Skill comes from
- how to pick inside that pool
- the obtain ceiling
- obtained vs learned vs grown
- Skills already held growing or evolving
- conversion and restore when a Class is lost or reclaimed
- what happens when a Skill offer is refused

This file does not answer:

- Class identity (`classes.md`)
- when a level fires, or capstone as a *level event* (`leveling.md`)
- Conditions (`conditions.md`). System colors: parked.
- magic
- a list of legal Skills

## How to use

If you have not walked Watch → Judge → Product on `the-system.md`, stop and do that first.

Open this file when the product in play is a Skill: obtained, learned, grown, conversion after demotion, or a refused Skill offer.

### Output

Grok ruling packet, not forum text.

Return:

1. Skill outcome options: none / obtain / learn / grow a held Skill / convert / restore / refuse / several small Skills. Do not pick one in silence. Narrator chooses.
2. Which Class pool
3. Two lists, both in-ceiling:
   - **List A — effects.** Plain-speech capabilities. No bracket names.
   - **List B — names.** Possible Skill titles only. Do not pair them 1:1 unless the narrator asks.
4. Mark which List A effects sit nearer current height, and which sit toward the ceiling.
5. A short reason on each option (deed, need, desire, mind, draw, or exertion)
6. Whether `classes.md` or `leveling.md` should open

Default stance: always give the narrator options, with a short reason for each option. Include obtain-new and grow-held when both could be honest (for example when a Class has stepped). Do not pick one in silence.

Narrator finalizes. Grok proposes. Do not lock List A to List B.

### Stops

- No Skill directory.
- No Class rename in this file.
- No level number in this file.
- No floating pool.
- Do not award past that pool’s ceiling. Narrator only beyond it.
- Example Skill names are illustrations. Do not require them.
- Always return List A (effects, no names) and List B (names, not glued to A) unless the narrator asks to pair them.
- If `leveling.md` is missing, do not invent capstone timing. Capstone here only means “rarer slot,” not when the level fires.
- Refused = the offered Skill dies. Deeds, events, and mindset stay. Lost-with-Class = Skill is stored with that Class. Do not store a refusal. Do not expire a stored Skill.
- System colors: parked. Do not invent a color key.

## What a Skill is

A Skill is a capability taken from a Class pool: handed as new (obtained), built as new from no foundation (learned), or refined from one they already hold (grown).

It is not a spell list. It is not a player catalog. Need and desire color the pick. They do not invent a pool the Class does not have.

## Which pool

Each Class has its own Skill pool. Hierarchy is how rich that pool is. Level is investment in it.

A [Guard] draws [Guard] deeds. They do not draw a [King] Skill because they wished they could.

If the Skill is not tied to leveling a Class, still use a real pool. When unsure, the Class they were actually living, not the one they wished.

If two Classes could own the Skill, use `classes.md` (who owns the deed). Then pick from that pool.

No floating pool.

## How to pick

From that pool the System may use:

- **Deed** — what they actually did
- **Need** — what the moment required
- **Desire** — what they were reaching for
- **Mind** — how they understand the path and the deed
- **Draw** — a plain pull from the same pool

A random draw is still from the correct pool. It is not a different physics.

Most picks sit near current height in that Class. The ceiling is the rare edge, not the normal landing.

Weaker Skills still happen. Several small Skills can land; so can one Skill, or growth of a held Skill. Default: list those as options. Do not decide how many in silence.

Stronger Skills happen as luck, need, desire, tragedy, a capstone slot, or exertion — they went past what their current height would normally bear.

Offer List A and List B. Mark which effects are nearer height. Do not glue a name to an effect unless asked.

## Ceiling

A Skill obtained, learned, or grown from that Class’s pool may sit **up to 20 levels above** that Class’s current height.

That is a ceiling, not an average. Most draws sit far under it.

Past the ceiling: narrator only. Grok returns in-ceiling options and stops.

Learned Skills still respect that pool. A learned Skill that would sit past the ceiling is narrator-only.

## Obtained, learned, grown

Three different products. Do not mash them.

**Obtained** — a *new* Skill the System hands (usually with a Class or a level). No prior Skill of that kind required.

**Learned** — a *new* Skill they built from no existing Skill foundation. Solo effort or a teacher. They are forming the foundation itself until the System acknowledges it. Uncommon. Same pool. Same ceiling. Not a secret of the System. It is rare enough that most people never hear of it unless they are, or meet, someone that capable and that person mentions it.

Target-learning a new Skill is hard. It needs enough understanding, imagination, and deeds aimed at that capability. For most people it is worse than living the Class and taking what the System hands. Highly capable, mentally fluid people with discipline, drive, and passion have an easier time. Average range people rarely succeed by chasing a specific new Skill.

Do not treat “learned” as a way around the pool or the ceiling. Do not treat a quiet practice year as learned by default. Do not call growth of a held Skill “learned.”

**Grown** — an *existing* Skill evolves or refines. They have been using it, experimenting with it, breaking through, or accumulating effort. It can also rise when the Class levels or the Class itself changes and that Skill comes up in power with it. The old form no longer fits; it becomes a stronger version of what they already had.

A grown Skill may reach that Class pool’s obtain ceiling when the circumstances earn it. It still cannot jump the ceiling, and it still cannot jump into another Class’s pool. Narrator only past the ceiling.

Do not hand a new Skill name when growing the old one tells the truth.

If obtained vs learned vs grown is unclear, inform the narrator. List the readings.

## Refuse

They may refuse a Skill. That is allowed.

Keep the deeds, events, and mindset that caused the offer. The offered Skill expires. It does not sit on the sheet waiting to be clicked. A later Skill must be earned again from what they still are and still do.

Do not store a refused Skill as if it were a lost Class Skill.

## Convert, store, restore

When a Class is lost or demoted (`classes.md`), Skills of that Class are stored with it. They are not deleted.

Skills may convert to fit the new, lower role. Conversion stays in-pool for the *new* Class. Do not convert a [King] Skill into a random combat Skill because it was strong.

Restore only as far as the role is reclaimed. Partial return is allowed: some stored Skills, or converted weaker forms. Full return of the Class can bring the stored Skills back. If conversion vs restore is unclear, inform the narrator.

If this file is being used and the Class identity is still in doubt, stop and open `classes.md`.

## Capstone (Skill side only)

Every ten levels in a Class is a rarer Skill slot. That is all this file says.

When the capstone *level* fires is `leveling.md`. After Level 50, the novels often hand a Skill more often — park the exact rate until `leveling.md`. Do not use that rumor to flood low-level characters with Skills.

## Examples

Not a catalog.

**Packet shape.** Level 8 [Guard], real year on the gate.
List A (effects): see in the dark at the post; hold longer than the body should; know which footfalls are wrong.
List B (names): proposed titles only, not glued to the lines above.
Most of List A sits near 8. One line may sit higher if exertion is real. Ceiling is 28. Narrator picks outcome and whether to name from List B.

**Draw.** Same person, no sharp need. A plain pull from the [Guard] pool still near height. Not a [General] Skill.

**Outlier under ceiling.** They survive a night that should have ended them, or they hold the gate past what their height should allow. A stronger [Guard] Skill still at or under 8+20. Not a [King] Skill.

**Past ceiling.** The fitting wonder would sit past 28. In-ceiling options only. Narrator decides the extreme.

**Off-level Skill.** They invent a way at the wheel with no [Potter] level. Use the [Potter] pool if that is the path they were living. Same ceiling.

**Learned.** They have no gate Skill. They spend a year trying to invent one from nothing, or train under someone who has it. Average discipline, no unusual mind. Usually fail; living the [Guard] path and taking an obtained Skill is the better route. A rare success is a *new* [Guard] pool Skill, under ceiling.

**Grown.** They already have a gate Skill. They refine it, push it, or the Class steps and that Skill rises with it. The old form no longer fits. It becomes a stronger version of the same Skill. That growth may sit near height or, if earned, toward the ceiling. Not past 28. Not a [King] Skill. Not “learned.”

**Refuse.** They are offered a killing Skill and refuse. Keep the fight and the mindset. The offered Skill expires.

**Convert / store.** [King] falls. King-pool Skills store on the sheet. Some may convert to the lower ruling Class. Do not delete them.

**Partial restore.** They reclaim part of the old role. Some stored Skills return, or return weaker. Not the full set unless the role is fully back.

**Player want.** They ask for a rare combat Skill after a quiet craft week. No matching pool or deed. Silence or a small in-path Skill. Not the requested Skill.

## Design notes

- Process and examples. No Skill list.
- Output is two lists: effects without names, and names without forced pairing.
- Default: options to the narrator, each with a short reason. Do not decide count, pairing, obtain-vs-grow, or learned-vs-obtained in silence.
- Obtained = new Skill handed. Learned = new Skill built from no foundation. Grown = existing Skill refined or raised with the Class.
- Learned is uncommon, not hidden. Most people never hear of it. Harder than leveling the Class for most people.
- Grown Skills may reach that pool’s ceiling when the old form no longer fits. Not past it.
- Ceiling is per Class pool, up to 20 above that Class’s current height.
- Off-level Skills use the Class they were living when unsure.
- Capstone rarity lives here. Capstone as a level event lives in `leveling.md`.
- Refused Skill expires. Stored-with-lost-Class does not.
- Colors and unique Skill names: parking lot.
